TRUST GRAPH + OPENTELEMETRY
Trust DAG: a trust-aware data plane
MLflow traces what happened inside the agent. Trust DAG captures the delegation chain across agents — and uses it to reconstruct lineage, detect anomalies, and enforce policy.
1

Observe

Proxy sidecars capture who delegated to whom at every hop. Trust metadata — principal, caller, target, hop kind — is propagated as headers and tagged on spans. The observation point sits outside the agent's trust boundary. A compromised agent cannot alter its own trace data. No SDKs, no agent code changes.

2

Reconstruct

A lineage service builds the actual delegation DAG from trust-tagged spans. Nodes are typed (principal, agent, resource). Each run is scored against learned baselines to detect novel edges, capability overreach, and anomalous patterns.

3

Enforce

The same proxy that observes calls out to pluggable policy engines to block high-risk requests before they reach the agent. Risk signals from the DAG, capability alignment, and external inputs like agent evals all feed into the verdict.

One infrastructure layer: observes delegation, reconstructs lineage, enforces policy
TRUST GRAPH + OPENTELEMETRY
Properties for security and ops
What this approach gives us beyond traditional agent tracing

Cross-boundary visibility

Captures delegation hops across heterogeneous agent systems — different teams, frameworks, runtimes. For third-party and external APIs, the egress sidecar captures the outbound edge: which agent called what, on whose behalf. Cross-domain federation is possible via W3C Trace Context tracestate where both sides participate.

Tamper-resistant audit trail

Spans are emitted by the Envoy sidecar, not the agent process. A compromised agent cannot alter its own trace data. The observation point is outside the agent's trust boundary.

Policy enforcement surface

Because observation happens at the proxy layer, it can evolve from passive tracing to active enforcement. The same sidecars that observe delegation could enforce capability policies — rejecting calls that violate declared agent permissions before they reach the target.

Zero agent instrumentation

No SDKs, no code changes, no framework dependencies inside agents. Works for any workload routable through the service mesh — HTTP, gRPC, WebSocket. Trust metadata propagates via W3C Trace Context tracestate, aligning with OTel's native propagation standard.

These properties are complementary to application-level tracing — together they cover the full stack from LLM internals to inter-service delegation.
